## 2. Conceptos clave (antes de programar)

### 2.1. Corpus, documento, frase, token
- **Corpus**: colección de textos (por ejemplo, un conjunto de tweets).
- **Documento**: un elemento del corpus (un tweet, un título, una noticia completa).
- **Token**: unidad que produce el tokenizador. Normalmente palabras, pero puede incluir signos o subpalabras (según el tokenizador).

### 2.2. Vocabulario e índices
- **Vocabulario**: conjunto de tokens distintos observados en el entrenamiento.
- **Índice**: entero asignado a cada token.
- Es habitual reservar:
  - `0` para **padding** (relleno).
  - (Opcional) un índice para **OOV** (out-of-vocabulary), tokens no vistos.

### 2.3. Secuencias y padding
Una red neuronal necesita tensores con tamaño fijo por batch. Como los textos tienen longitudes variables:
- Convertimos cada documento a una **secuencia de índices**.
- Aplicamos **padding** hasta `max_length`:
  - `padding="post"` añade ceros al final.
  - `truncating="post"` corta por el final si supera `max_length`.

### 2.4. Capa Embedding
La capa `Embedding(input_dim, output_dim)` aprende un vector denso por token:
- `input_dim`: tamaño del vocabulario (número de índices posibles).
- `output_dim`: dimensión del vector (p. ej. 50, 100, 300).
- Salida: para cada texto (secuencia de longitud `max_length`), produce una matriz `max_length × output_dim`.

### 2.5. Clasificación binaria, sigmoid y pérdida
En clasificación binaria usamos:
- **Sigmoid** en la salida: devuelve $p(y=1 | x)$ en $(0,1)$.
- **Binary cross-entropy** como pérdida:
$$
L = -(1/N) * sum_{i=1..N} [ y_i * log(p_i) + (1 - y_i) * log(1 - p_i) ]
$$

> [!warning] Importante sobre las etiquetas
> En estos listados, para clasificación binaria:
> - `1` suele indicar **positivo** (sentimiento) o **Fake** (según ejercicio).
> - `0` suele indicar **negativo** o **True**.
> Mantén esto consistente en todo el pipeline (carga de datos, entrenamiento, evaluación).

### 2.6. Sobre-aprendizaje (overfitting) y curvas de aprendizaje
- **Overfitting**: el modelo memoriza entrenamiento, pero falla en validación/test.
- Señal típica: `accuracy_train` sube, `accuracy_val` se estanca o baja; `loss_val` sube.
- Se mitiga con: **Dropout**, menos capas, regularización, más datos, early stopping.

## 3. Esquema general del pipeline (aplicable a todos los ejercicios)

```mermaid
flowchart TD
  A[Datos brutos: textos + etiquetas] --> B[Split: train/val/test]
  B --> C[Vocabulario SOLO con train]
  C --> D[Codificación: textos -> secuencias de índices]
  D --> E[Padding/Truncado a max_length]
  E --> F[Modelo: Embedding + (CNN/RNN/LSTM/...) + Dense]
  F --> G[Compilación: optimizer + loss + metrics]
  G --> H[Entrenamiento: fit()]
  H --> I[Evaluación: test + métricas]
  H --> J[Diagnóstico: curvas train/val]
```

> [!important] Regla de oro
> El vocabulario y cualquier estadística (por ejemplo, normalización) se ajustan SOLO con entrenamiento. Usar también validación/test para construir vocabulario introduce fuga de información (data leakage).

## 4. Ejercicio 1 (Listado 1): Clasificación de sentimiento con un dataset mínimo

### 4.1. Qué pide el enunciado
- Dataset de 4 frases en español con etiquetas:
  - Negativo → `0`
  - Positivo → `1`
- Sin “preprocesamiento” (no limpieza sofisticada; tokenización básica sí es necesaria).
- `max_length = 10`, `vocab_size = 50`
- Construir:
  1) vocabulario (token → índice)  
  2) matriz documentos-términos (aquí implementada como secuencias de índices con padding)  
  3) modelo simple con `Embedding` y salida binaria  
  4) entrenar y probar con frases nuevas

### 4.2. Datos de partida
```python
sentences = [
    "Estoy un poco harto del día a día, nada mejora",
    "Hoy es un buen día",
    "No se te ve satisfecho con el trabajo",
    "Este paisaje es hermoso y bonito"
]
labels = [0, 1, 0, 1]  # 1: positivo, 0: negativo
```

### 4.3. Paso 1: Tokenización y vocabulario (token → índice)
Una forma sencilla es usar spaCy solo como tokenizador (sin lematizar ni eliminar stopwords):

```python
import spacy
from tensorflow.keras.preprocessing.sequence import pad_sequences

# Cargar el modelo de spaCy en español
nlp = spacy.load("es_core_news_sm")

def build_vocabulary(corpus, vocab_size):
    """Crea un diccionario token->índice.
    - Reservamos 0 para padding.
    - Empezamos en 1 para no mezclar tokens con padding.
    - Cortamos al llegar a vocab_size-1 (por el 0).
    """
    token_to_index = {}
    current_index = 1

    for text in corpus:
        doc = nlp(text)
        for token in doc:
            t = token.text
            if t not in token_to_index and current_index < vocab_size:
                token_to_index[t] = current_index
                current_index += 1

    return token_to_index

vocab_size = 50
vocabulary = build_vocabulary(sentences, vocab_size)

print("Vocabulario (token -> índice):")
for tok, idx in vocabulary.items():
    print(f"  {idx:2d}: {tok}")
```

**Salida esperada (ejemplo orientativo)**  
Verás un listado de tokens, por ejemplo:
- `Estoy`, `un`, `poco`, `harto`, `del`, `día`, `a`, `día`, `,`, `nada`, `mejora`, etc.  
El orden exacto depende del tokenizador y del texto.

> [!note] Qué significa “matriz documentos-términos” aquí
> El enunciado describe una matriz donde cada posición contiene el índice del término del vocabulario. Eso se corresponde con una **representación secuencial** tipo:
> - documento 1 → `[12, 5, 33, 7, ...]`
> - con padding a longitud fija.  
> No es una bolsa de palabras (bag-of-words); aquí importa el orden.

### 4.4. Paso 2: Codificación de textos y padding a `max_length`
```python
def encode_and_pad(corpus, vocabulary, max_length):
    encoded = []
    for text in corpus:
        doc = nlp(text)
        seq = []
        for token in doc:
            seq.append(vocabulary.get(token.text, 0))  # 0 si no está
        encoded.append(seq)

    # padding a la derecha; truncado a la derecha si es necesario
    encoded_pad = pad_sequences(
        encoded, maxlen=max_length, padding="post", truncating="post"
    )
    return encoded_pad

max_length = 10
X = encode_and_pad(sentences, vocabulary, max_length)

print("Matriz (docs x max_length):")
print(X)
```

**Salida esperada (ejemplo)**  
Una matriz `4 × 10` de enteros.  
- Cada fila es una frase.
- Los ceros al final son padding.

### 4.5. Paso 3: Definición del modelo (Embedding + salida binaria)
Para un ejemplo de juguete, un modelo mínimo puede ser:

```python
import tensorflow as tf
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Embedding, Flatten, Dense

vector_size = 8  # dimensión del embedding (pequeña por ser ejemplo didáctico)

model = Sequential([
    Embedding(input_dim=vocab_size, output_dim=vector_size, input_length=max_length),
    Flatten(),
    Dense(1, activation="sigmoid")
])

model.compile(
    optimizer="adam",
    loss="binary_crossentropy",
    metrics=["accuracy"]
)

model.summary()
```

**Qué deberías ver en `model.summary()`**  
- Una capa `Embedding` con parámetros: `vocab_size * vector_size`
- Una capa `Flatten`
- Una capa `Dense` con 1 neurona

> [!warning] Por qué se usa Flatten aquí
> `Embedding` produce un tensor 2D por ejemplo: `max_length × vector_size`.  
> Una capa `Dense` necesita un vector 1D, así que se aplana.  
> En modelos más realistas, se suele usar CNN/RNN/Pooling en lugar de aplanar todo.

### 4.6. Paso 4: Entrenamiento y validación
Con tan pocos datos, el objetivo es que el código funcione, no obtener métricas “fiables”.

```python
import numpy as np
from sklearn.model_selection import train_test_split

y = np.array(labels)
X_train, X_val, y_train, y_val = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y
)

history = model.fit(
    X_train, y_train,
    validation_data=(X_val, y_val),
    batch_size=32,
    epochs=5,
    verbose=1
)
```

### 4.7. Paso 5: Predicciones con nuevas frases (salida esperada)
```python
test_sentences = [
    "No fui al estreno de la película porque nadie me quería acompañar",
    "Envidio de buena manera a los que tienen la oportunidad de ir mañana al estadio",
    "Se nos está volviendo costumbre del domingo por la noche ver SNL y eso me hace recibir el lunes con mejor humor",
    "Al final decidí no ir al cine porque estaba cansada",
    "Todo es maravilloso y formidable, muy bonito"
]

X_test = encode_and_pad(test_sentences, vocabulary, max_length)
probs = model.predict(X_test)

for text, p in zip(test_sentences, probs):
    p = float(p[0])
    pred = 1 if p > 0.5 else 0
    print("-"*60)
    print("Texto:", text)
    print(f"Probabilidad clase 1 (positivo): {p:.4f}")
    print("Predicción:", "Positivo" if pred==1 else "Negativo")
```

**Interpretación correcta**
- La red devuelve una probabilidad.
- Se suele usar umbral `0.5` para decidir 0/1.

> [!note] Si obtienes predicciones “raras”
> Es normal: 4 frases no son suficientes para generalizar. Lo importante es que:
> 1) el pipeline no tiene errores,
> 2) las dimensiones cuadran,
> 3) la red aprende algo en entrenamiento.

### 4.8. Checklist de errores típicos
- Confundir `0` como token real (debe ser padding).
- Construir vocabulario con datos de test.
- `vocab_size` y `input_dim` inconsistentes.
- Olvidar `max_length` o cambiarlo a mitad.
- Mezclar etiquetas (positivo=0 por error).

### 5.5. CNN 1D para texto (arquitectura base)
Una CNN 1D detecta patrones locales (n-gramas) sobre la secuencia de embeddings.

```python
import tensorflow as tf
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Embedding, Conv1D, GlobalMaxPooling1D, Dense, Dropout

embedding_dim = 64

model = Sequential([
    Embedding(input_dim=vocab_size, output_dim=embedding_dim, input_length=max_length),

    Conv1D(filters=128, kernel_size=5, activation="relu"),
    GlobalMaxPooling1D(),

    Dropout(0.5),
    Dense(64, activation="relu"),
    Dense(1, activation="sigmoid")
])

model.compile(
    optimizer="adam",
    loss="binary_crossentropy",
    metrics=["accuracy"]
)

model.summary()
```

**Intuición**  
- `kernel_size=5` mira ventanas de 5 tokens (aprox. 5-gramas sobre embeddings).
- `GlobalMaxPooling1D` toma el máximo por filtro: “si detecto un patrón en algún punto del texto, me quedo con la activación más fuerte”.

### 5.6. Experimentos recomendados (lo que suele pedir “probar configuraciones”)
Tabla de variantes típicas:

| Componente | Variante | Qué cambia |
|---|---|---|
| `embedding_dim` | 50 / 100 / 200 | capacidad de representación |
| `filters` | 64 / 128 / 256 | número de detectores de patrones |
| `kernel_size` | 3 / 5 / 7 | tamaño de n-grama detectado |
| nº conv layers | 1 / 2 / 3 | jerarquía de patrones |
| pooling | max / global max | reducción de secuencia |
| regularización | Dropout 0.2–0.6 | overfitting |
| optimizador | Adam / RMSprop | dinámica de entrenamiento |

### 5.8. Pregunta del enunciado: ¿mejora con preprocesamiento básico?
Preprocesamiento básico propuesto:
- eliminar stopwords,
- eliminar puntuación,
- lematizar.

Por qué puede mejorar:
- Reduce ruido (hashtags irrelevantes, signos, variaciones morfológicas).
Por qué puede empeorar:
- Pierdes señales útiles (negaciones, emoticonos, signos de exclamación, intensificadores).
- En tweets, “ruido” a veces es información.

Ejemplo de preprocesamiento con spaCy (opcional):
```python
import spacy
nlp = spacy.load("es_core_news_sm")

def preprocess_spacy(text):
    doc = nlp(text.lower())
    lemmas = []
    for tok in doc:
        if tok.is_punct:
            continue
        if tok.is_space:
            continue
        if tok.is_stop:
            continue
        lemmas.append(tok.lemma_)
    return " ".join(lemmas)

texts_clean = [preprocess_spacy(t) for t in texts[:5]]
print(texts[0])
print(texts_clean[0])
```

> [!warning] No elimines negaciones a ciegas
> Palabras como “no”, “nunca”, “jamás” suelen ser stopwords, pero son cruciales para sentimiento.
> Si haces stopword removal, considera mantener negaciones.

```python
print("Dimensión:", w2v.vector_size)  # 300

```

### 6.3. Construir la matriz de embeddings alineada con tu vocabulario
El punto crítico: tu `Tokenizer` genera un `word_index` (palabra → índice).  
Hay que construir `embedding_matrix` tal que:
- `embedding_matrix[idx]` sea el vector Word2Vec de esa palabra,
- si la palabra no existe en Word2Vec, se deja en ceros o aleatorio pequeño.

```python
import numpy as np

embedding_dim = w2v.vector_size  # 300

word_index = tokenizer.word_index  # dict palabra->índice (incluye <OOV>)
num_words = min(vocab_size, len(word_index) + 1)

embedding_matrix = np.zeros((num_words, embedding_dim), dtype=np.float32)

hits, misses = 0, 0
for word, idx in word_index.items():
    if idx >= num_words:
        continue
    if word in w2v:
        embedding_matrix[idx] = w2v[word]
        hits += 1
    else:
        misses += 1

print("Embeddings encontrados:", hits)
print("Embeddings no encontrados:", misses)
```

### 6.4. Crear una capa Embedding precargada
```python
from tensorflow.keras.layers import Embedding

embedding_layer = Embedding(
    input_dim=num_words,
    output_dim=embedding_dim,
    weights=[embedding_matrix],
    input_length=max_length,
    trainable=False  # prueba también True (fine-tuning)
)
```

Luego sustituyes la capa `Embedding(...)` del modelo CNN por `embedding_layer`.

> [!note] trainable=False vs trainable=True
> - `False`: conserva la semántica original Word2Vec; útil con pocos datos.
> - `True`: ajusta embeddings a tu tarea; útil con muchos datos y cuidado de overfitting.

### 7.3. Análisis exploratorio de longitudes (para decidir max_length)
Conviene medir **número de palabras** o **número de tokens**:

```python
import numpy as np

def word_lengths(texts):
    return np.array([len(t.split()) for t in texts], dtype=np.int32)

len_head = word_lengths(texts_headline)
len_body = word_lengths(texts_body)

print("Headline: p50/p90/p95 =", np.percentile(len_head, [50, 90, 95]))
print("Text:     p50/p90/p95 =", np.percentile(len_body, [50, 90, 95]))
```

Criterio típico:
- `max_length` ≈ percentil 90–95 (balance entre cubrir longitud y no inflar coste).

> [!note] Diferencia títulos vs contenido
> - Títulos: secuencias cortas, RNN entrena más rápido.
> - Contenido: secuencias largas, más coste y más riesgo de truncar información.

### 7.5. Preprocesamiento básico + Tokenizer (vocabulario)
Puedes reutilizar el preprocesamiento con spaCy (lematización y stopwords).  
En fake news, cuidado: algunas stopwords pueden aportar estilo periodístico; experimentar es parte del ejercicio.

```python
import spacy
nlp = spacy.load("es_core_news_sm")

def preprocess(text):
    doc = nlp(text.lower())
    out = []
    for tok in doc:
        if tok.is_space or tok.is_punct:
            continue
        # Mantener negaciones aunque sean stopwords
        if tok.is_stop and tok.lemma_ not in ["no", "nunca", "jamás"]:
            continue
        out.append(tok.lemma_)
    return " ".join(out)

head_train_p = [preprocess(t) for t in head_train]
head_val_p   = [preprocess(t) for t in head_val]
head_test_p  = [preprocess(t) for t in head_test]
```

## 8. Ejercicio 2 (Listado 2): LSTM para fake news

### 8.1. Por qué LSTM suele mejorar a SimpleRNN
Una SimpleRNN sufre al retener dependencias largas por desvanecimiento/explosión del gradiente.  
LSTM introduce compuertas (gates) que controlan qué información se:
- olvida,
- añade,
- expone a la salida.

### 8.2. Sustitución directa: SimpleRNN → LSTM
Para títulos:

```python

model_lstm_head = Sequential([
    Embedding(input_dim=vocab_size, output_dim=embedding_dim, input_length=max_length_head),

    Dense(1, activation="sigmoid")

model_lstm_head.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
history = model_lstm_head.fit(
    Xh_train_seq, y_train,
```

### 8.3. Qué experimentar (como pide el enunciado)
- `units`: 32 / 64 / 128
- `embedding_dim`: 50 / 100 / 200
- `dropout`, `recurrent_dropout`: 0.1–0.5
- Añadir `Dense(64, relu)` antes de la salida
- Early stopping

## 9. Ejercicio 3 (Listado 2): BiLSTM para fake news

### 9.1. Qué es una BiLSTM
Una **LSTM bidireccional** procesa la secuencia:
- de izquierda a derecha,
- y de derecha a izquierda,
y concatena ambas representaciones.  
Esto ayuda cuando la evidencia puede aparecer antes o después en la frase.

### 9.2. Configuración de referencia del enunciado
![[Listado2Ejercicios_Tema4_PLN.pdf#page=4&rect=0,0,595,842|Listado2Ejercicios_Tema4_PLN, p.4]]

### 9.3. Arquitectura base (similar a la propuesta)
```python
from tensorflow.keras import Sequential
from tensorflow.keras.layers import Embedding, Bidirectional, LSTM, Dropout, Dense

DROPOUT = 0.4

model_bilstm = Sequential([
    Embedding(input_dim=vocab_size, output_dim=embedding_dim, input_length=max_length_head),

    Bidirectional(LSTM(60, return_sequences=True, recurrent_dropout=0.2)),
    Dropout(DROPOUT),

    Bidirectional(LSTM(32, recurrent_dropout=0.2)),
    Dropout(DROPOUT),

    Dense(60, activation="relu"),
    Dense(1, activation="sigmoid")
])

model_bilstm.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
model_bilstm.summary()
```

### 9.4. Cómo decidir el número óptimo de capas
No existe una fórmula cerrada; el enunciado sugiere lo correcto: **experimentos**.
Buenas prácticas:
- Empieza simple (1 BiLSTM).
- Añade complejidad si:
  - `train` y `val` son ambos bajos (underfitting).
- Reduce complejidad o añade regularización si:
  - `train` alto, `val` bajo (overfitting).
- Usa early stopping + guardar mejor modelo.

```python
from sklearn.metrics import f1_score

best_t, best_f1 = 0.5, -1
```

## 11. Glosario de términos difíciles

- **Epoch**: una pasada completa por el conjunto de entrenamiento.
- **Batch**: subconjunto del entrenamiento usado para una actualización de pesos.
- **Optimizer (Adam, RMSprop)**: método que ajusta pesos para minimizar la pérdida.
- **Loss (binary_crossentropy)**: función objetivo a minimizar.
- **Metric (accuracy)**: medida informativa (no siempre la mejor para desbalance).
- **Dropout**: apaga neuronas aleatoriamente durante entrenamiento para regularizar.
- **Recurrent dropout**: dropout aplicado a conexiones recurrentes (en RNN/LSTM).
- **Embedding**: vector denso que representa un token.
- **OOV**: token no visto en entrenamiento.
- **Padding**: relleno con ceros para igualar longitudes.
- **Truncating**: cortar secuencias largas para ajustarlas a `max_length`.
- **Overfitting**: el modelo aprende ruido del train y falla fuera del train.
- **Underfitting**: el modelo es demasiado simple para capturar el patrón.
